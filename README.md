# 자재플로우 · Material Flow

HTML / CSS / JavaScript만으로 동작하는 자재관리 웹 프로그램입니다. 프레임워크, 백엔드, 데이터베이스 없이 GitHub Pages에서 사용합니다.

## 기능
- 대시보드: 전체 품목, 재고 금액, 부족 품목, 당일 입출고 건수
- 편집 가능한 자재 그리드: 등록, 수정, 삭제, 검색, 분류·창고·상태 필터, 정렬, 페이지 이동
- 자재 정보: 코드, 이름, 규격, 분류, 단위, 창고, 위치, 거래처, 현재 재고, 안전재고, 단가
- 입고·출고·재고 조정: 추가, 수정, 삭제와 재고 자동 재계산
- 재고 초과 출고 방지 및 중복 코드 방지
- 안전재고 이하·품절 표시, 창고별 품목 수·재고 금액·부족 품목 리포트
- 최근 7일 입출고와 분류별 재고 금액 차트 (CSS로 구현)
- JSON 전체 내보내기 및 검증 후 가져오기

## JSON과 저장
초기 가상 데이터는 `data/seed.json`에 있습니다. 브라우저에서 수정하면 localStorage에 JSON 문자열로 저장하며 새로고침 후에도 유지됩니다. 데이터베이스나 서버 저장은 사용하지 않습니다.

데이터 형식: `version: 1`, `items: []`, `movements: []`. 자재는 `opening`(기초재고)을 갖고 현재 재고는 **기초재고 + 입고 − 출고 + 조정**으로 계산합니다. 그리드에서 현재 재고를 수정하면 조정 기록을 자동 생성합니다. 이력이 있는 자재는 직접 삭제할 수 없습니다.

내보낸 JSON으로 데이터 전체를 백업할 수 있습니다. 가져오기는 현재 데이터 전체 교체이며 확인 창이 있습니다. 중복 코드·ID, 잘못된 참조, 음수 현재 재고, 잘못된 날짜·수량 등을 거부합니다. 가져오기 한도는 10MB / 자재 5,000종 / 기록 30,000건입니다.

## 실행 / 배포
- GitHub Pages: Settings → Pages → Source → GitHub Actions
- `.github/workflows/pages.yml`이 main 변경을 자동 배포합니다.
- 로컬: 프로젝트 폴더에서 `python3 -m http.server 8000`, 브라우저로 `http://localhost:8000` 접속
- 파일을 더블클릭하는 `file://` 방식은 JSON fetch와 JS 모듈 보안 정책 때문에 지원하지 않습니다.
- 테스트: Node.js로 `node --test tests/core.test.js`. Node는 테스트에만 필요하며 웹 화면 실행에는 필요 없습니다.

## 주의할 범위
- 기기·사용자 간 자동 동기화는 없습니다. JSON을 내보내고 다른 기기에서 가져오세요.
- 브라우저 저장 데이터 삭제, 시크릿 창 종료 시 데이터가 사라질 수 있습니다. 정기적으로 JSON을 백업하세요.
- 여러 탭에서 동시에 수정하면 마지막 저장이 우선하며 다른 탭 변경 알림을 표시합니다.
- 과거 시점의 재고 부족 검증은 없으며 현재 합계 재고가 음수가 되는 작업을 차단합니다.
- 재고 금액은 현재 수량 × 현재 등록 단가입니다. 회계상 선입선출·이동평균 원가는 계산하지 않습니다.
- 자재의 창고와 위치는 관리 정보입니다. 창고 간 이동 장부, 로트 추적, 바코드 장비, 구매 발주, 인증 및 불변 감사 장부는 제공하지 않습니다.
- 단위가 서로 다른 수량의 합계는 금액과 구분합니다. 7일 차트는 입출고 수량의 단순 합계임을 화면에 명시합니다.
- 외부 글꼴을 사용할 수 없는 환경에서는 시스템 글꼴로 동작합니다.
